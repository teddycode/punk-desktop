# 跨链区页面布局与视觉设计规划

版本：V1.0  
日期：2026-09-17  
适用项目：PunkOS Desktop  
文档状态：规划稿，待审阅后实施

## 1. 规划目标与范围

参考新版存储区的页面风格与业务流程设计，将跨链区组织为六个一级业务页面，并配套统一的任务、链、交易和区块详情页。

核心目标是让首次进入的用户知道从哪里开始，能顺着页面完成任务发起、进度跟踪和结果查看；同时为中继参与者与管理者提供清晰的操作路径。

本规划覆盖前端导航、页面拆分、布局、交互状态、视觉规范、列表分页与实施顺序。文中提出的页面与组件均为拟议设计，不代表已经实现。本规划不预设新增合约能力、任意链互通或资产转账能力，具体业务以当前已注册任务类型和实际支持的链路为准。

规划依据为当前仓库中的路由、页面模板、交互代码和存储区打包样式；未完成运行态视觉验收。

## 2. 当前结构与调整方向

当前跨链区默认进入“浏览器”，同时提供“搬运工”“管理者”“跨链任务”“中继者”等入口。任务发起、执行、脚本准备与网络查询分别位于不同页面，用户需要自行理解它们之间的关系。

| 当前页面 | 当前承担的主要功能 | 规划中的归属 |
| --- | --- | --- |
| `Multichain.vue` | 系统概览、源链列表 | 跨链网络；部分摘要复用到跨链工作台 |
| `Bridge.vue` | 链与桥信息、业务交易、影子区块、传输任务、搬运工、控制交易 | 跨链网络的链详情 |
| `CrossChainTasks.vue` | 选择任务类型，通过弹窗填写 Payload 与费用 | 发起跨链分步页面 |
| `CrossTasksCreated.vue` | 扫描任务、接单、提交证明、中继者质押管理 | 中继工作台；复用任务读取能力支撑我的任务 |
| `Relay.vue` | 全节点准备说明、搬运脚本与运行包下载 | 中继工作台的区块搬运标签 |
| `Manager.vue` | 注册源链、注册任务类型、委员会管理 | 跨链管理的三个标签 |
| `Transaction.vue` / `Block.vue` | 交易、区块详情 | 统一的下钻详情页 |

应借鉴存储区的三个关键特点：

1. 用业务动作组织页面，例如选择、填写、确认、执行、查看结果。
2. 为复杂操作提供分步引导，同时保留当前对象和操作摘要。
3. 成功后承接下一步，失败后提供解释与恢复入口。

## 3. 导航与页面分页

### 3.1 一级导航

跨链区内部采用左侧导航，顶部统一展示钱包、当前签名网络、服务连接状态和主题切换。与桌面现有外层导航协调，避免重复出现两套同级菜单。

普通用户入口排列在前，中继与管理入口在后分组展示。默认进入“跨链工作台”。

| 一级页面 | 用户目标 | 页内分区或标签 |
| --- | --- | --- |
| 跨链工作台 | 找到第一步，继续未完成任务 | 快速开始、我的进行中任务、网络摘要 |
| 发起跨链 | 选择业务并创建任务 | 选择业务与链路、填写业务内容、核对并提交 |
| 我的任务 | 跟踪自己发起的任务，查看最终结果 | 全部、进行中、已成功、已失败 |
| 跨链网络 | 查看已接入链、桥状态与链上记录 | 链列表、链详情、交易详情、区块详情 |
| 中继工作台 | 准备运行环境、接单与执行 | 任务执行、区块搬运、身份与质押 |
| 跨链管理 | 管理链接入、业务类型与委员会 | 链接入、业务类型、委员会 |

单个任务、单条链、单笔交易和单个区块采用可独立访问的详情页，不占一级导航。短操作使用弹窗，复杂执行流程使用完整页面。

“区块搬运”和“任务执行”仅归入同一运营入口，各自保留业务含义、资格与状态。运行搬运脚本不能在界面上被等同于获得任务接单资格。

### 3.2 主要业务链路

普通用户：

```text
进入跨链工作台
→ 选择业务与受支持链路
→ 填写业务内容
→ 核对费用与提交账户
→ 钱包确认并创建任务
→ 自动进入任务详情
→ 跟踪接单、执行、证明验证
→ 查看最终结果与关联交易
```

任务中继参与者：

```text
进入中继工作台
→ 查看身份与质押要求
→ 完成适用的资格准备
→ 选择并确认接单
→ 执行任务
→ 回填并核对执行证明
→ 提交验证
→ 查看任务结果
```

区块搬运参与者：

```text
选择源链
→ 准备全节点
→ 获取运行包
→ 按说明配置与启动
→ 查看可获取的同步信息
```

## 4. 跨链工作台

### 4.1 页面目标

让用户迅速回答三个问题：我可以做什么、我正在做什么、现在需要我做什么。

### 4.2 布局

采用“标题说明 + 轻量统计 + 主次双栏”，参考存储区工作台的内容密度与卡片层级。

```text
┌─────────────────────────────────────────────────────┐
│ 跨链工作台                          钱包 / 当前网络   │
│ 发起跨链请求，跟踪执行过程与链上结果                  │
├─────────────────────────────────────────────────────┤
│ 我的进行中任务    待我处理    可用链路                │
├──────────────────────────────┬──────────────────────┤
│ 开始一次跨链                 │ 当前环境             │
│ 选择业务 → 填写内容 → 跟踪结果 │ 钱包、网络、服务连接 │
│ [发起跨链]                   │ 对应的处理入口       │
├──────────────────────────────┤                      │
│ 最近任务                     │ 网络摘要             │
│ 业务 / 链路 / 当前步骤 / 操作 │ 已接入链与可用状态   │
└──────────────────────────────┴──────────────────────┘
```

### 4.3 内容与行为

- 首次进入时，显示简短流程说明与“发起跨链”主按钮。
- 已有任务时，突出进行中任务与“查看进度”入口。
- 当前环境卡分别说明钱包、签名网络与服务连接状态，并提供对应处理动作。
- 网络摘要只展示有数据支撑的可用链与状态，不以合约地址、哈希占据首屏。
- 统计数据暂不可获取时显示“暂无数据”，不显示误导性的零值。

## 5. 发起跨链

### 5.1 页面目标与布局

将现有发起弹窗改为完整分步页面。左侧约三分之二为操作区，右侧约三分之一为实时任务摘要。

```text
选择业务与链路 → 填写业务内容 → 核对并提交 → 查看任务进度
```

### 5.2 第一步：选择业务与链路

通过业务卡片展示名称、一句话用途、支持链路和可用状态。只有实际支持的业务与链路能够继续。

需要在实施前统一“业务执行方向”和“签名提交网络”的语义。当前发起页固定展示目标为 Hub，执行页又包含反向链路配置，因此不能直接把现有字段名拼成对用户的方向说明。

建议在选择区域分别展示：

- 业务涉及的链与执行方向。
- 本次创建任务需要签名的网络。
- 不可用组合的原因与适用的下一步。

### 5.3 第二步：填写业务内容

- 对已有明确数据结构的任务类型，提供对应业务表单。
- 对通用 Payload 类型，保留文本和 Hex 输入，并提供格式说明、示例与校验结果。
- 验证器地址、原始编码等专业信息放在可展开区域。
- 返回上一步时保留已填写内容；变更任务类型导致内容不兼容时明确提示。

### 5.4 第三步：核对并提交

集中展示业务名称、链路、提交账户、业务内容摘要、任务奖励与网络手续费。右侧摘要随填写实时更新，签名前可返回修改。

费用单位与实际网络一致。现有固定 `~0.002 PUNK` 不应作为实时估算呈现；没有可靠估算时显示“以钱包确认为准”。

### 5.5 提交结果

区分等待钱包确认、交易已发送、创建已确认。创建确认后进入任务详情，展示“已创建，等待接单”等真实业务状态。创建成功不等于跨链执行成功。

## 6. 我的任务与任务详情

### 6.1 任务列表

新增面向发起人的任务入口，默认仅展示当前账户发起的任务。

列表主列为：业务名称、链路、创建时间、奖励或费用、当前状态、查看详情。完整任务 Key、地址与 Payload 放在详情中。

提供全部、进行中、已成功、已失败标签，并支持按业务、链路和任务编号筛选。

### 6.2 任务详情布局

| 区域 | 内容 |
| --- | --- |
| 顶部摘要 | 任务名称、链路、当前状态或结果 |
| 执行时间线 | 各阶段状态、时间与可用证据 |
| 业务详情 | 输入内容、执行者、关联交易、结果 |
| 侧边说明 | 当前在等待什么、是否需要用户操作、下一步入口 |
| 高级信息 | 原始 Payload、完整地址、证明等专业字段 |

规划中的时间线为：

```text
创建确认 → 等待接单 → 执行中 → 证明提交与验证 → 成功 / 失败
```

具体步骤必须由链上状态、事件或执行证据支撑。当前无法区分的阶段可合并展示；缺少证据时显示“暂无确认信息”，不模拟完成进度。

失败时展示可理解的原因与适用操作，例如查看失败交易、核对输入、修改后重新发起。仅在实际能力支持时提供重试或其他动作。

关闭页面后能够根据任务编号重新进入；从详情返回列表时恢复筛选、页码与阅读位置。

## 7. 跨链网络与链上详情

### 7.1 链列表

将现有“浏览器”入口改为“跨链网络”，沿用存储节点市场的卡片浏览方式。

- 顶部：页面说明、搜索与状态筛选。
- 主体：链卡片，展示名称、可用状态、最新已知高度、支持的业务。
- 主操作：查看链详情。
- 次操作：当链路可用时，使用此链发起任务，并带入选择上下文。
- 合约地址：保留查看与复制，降低视觉优先级。

### 7.2 链详情

保留现有业务能力，使用页内标签整理为：概览、业务交易、传输任务、影子区块、搬运参与者、控制交易。

默认进入概览，展示业务可用状态和关键摘要。专业记录通过标签访问，避免首屏堆积所有字段。

### 7.3 交易与区块详情

统一采用“结果摘要—关键字段—关联记录”。任务、交易、区块之间提供有数据支撑的关联跳转；无法解析的关联显示原因，不生成无效链接。

## 8. 中继工作台

### 8.1 页内标签

| 标签 | 主要布局与流程 |
| --- | --- |
| 任务执行 | 待接单、我执行的任务；接单确认、执行、证明核对与提交、查看结果 |
| 区块搬运 | 选择源链、准备全节点、获取运行包、配置与启动说明、已有同步信息 |
| 身份与质押 | 当前资格、已质押、还需补足、追加与提取操作 |

### 8.2 执行详情

将包含脚本运行、链选择、RPC、交易高度等内容的现有“提交证明”弹窗整理为完整执行详情页。

左侧按步骤完成操作，右侧固定展示任务上下文与当前状态。自动回填后提供核对界面；手动参数、原始证明和运行日志放入高级信息区域。

资格不足时，解释缺少的条件并链接到身份与质押页面。已由他人接单、已完成等状态展示对应说明，不提供无效操作。

### 8.3 区块搬运准备

下载入口保留版本、适用链与必要运行条件。没有自动检测能力的环节展示说明与“尚未验证”；点击下一步不代表全节点已同步或搬运器已运行。

## 9. 跨链管理

采用“链接入 / 业务类型 / 委员会”三个标签，各标签保留一个明确主操作。

| 标签 | 主要内容 | 主操作 | 成功后的承接 |
| --- | --- | --- | --- |
| 链接入 | 已注册链与配置详情 | 注册源链 | 查看已注册链 |
| 业务类型 | 已注册任务类型、适用链路与验证器 | 新增业务类型 | 查看业务类型详情 |
| 委员会 | 成员、邀请与移除进度 | 邀请成员 | 查看邀请或成员状态 |

根据当前账户权限展示可执行操作；仅用于浏览时明确标识只读状态。简短操作使用统一弹窗，复杂配置视内容长度采用独立页面或分步表单。

## 10. 视觉与 Style 规范

### 10.1 参考方向

采用存储区的绿系强调色、圆角面板、轻量统计、状态标签与主次双栏。现有跨链页中的蓝色、Emoji 标题和不同弹窗样式统一到同一套规范。

### 10.2 色彩与尺寸

| 项目 | 规划规范 |
| --- | --- |
| 浅色主题主色 | `#8DB800` |
| 辅助色 | `#13B984` |
| 强调方式 | 主按钮与小面积标题区域使用黄绿到青绿渐变 |
| 浅色主题底色 | 浅灰绿，搭配白色卡片 |
| 深色主题底色 | `#111816` |
| 深色卡片 | `#18211E` |
| 深色边框 | `#273530` |
| 深色强调色 | `#C9FF1A` |
| 深色正文 | `#DCE5E2` |
| 深色辅助文字 | `#9BB0A9` |
| 内容最大宽度 | 约 1400px |
| 页面内边距 | 常规 24px，窄窗口 16px |
| 区块间距 | 常规 20px，窄窗口 16px |
| 圆角 | 大面板 20px、卡片 16px、按钮与输入框 10–12px |
| 字号 | 页面标题 24px、区块标题 18px、正文 14px、辅助信息 12px |
| 动效 | 约 150–250ms，轻阴影、边框与状态过渡 |

### 10.3 组件与交互规则

- 每页一个清晰主操作，次操作采用描边或文字按钮。
- 统一线性图标，避免使用 Emoji 表达主要导航和标题。
- 成功、处理中、等待、失败分别使用语义色，并配合文字与图标。
- 地址与哈希使用等宽字体，支持截断、完整查看和复制。
- 按钮禁用时说明原因；输入错误就地展示，保留用户已填内容。
- 渐变背景上的文字检查对比度，根据底色使用合适文字颜色。
- 键盘焦点可见，状态不能仅通过颜色区分。
- 主题跟随桌面设置，模块内状态保持一致。

### 10.4 响应式与滚动

宽窗口采用双栏，小于约 1024px 时改为单栏，摘要移到表单附近。统计卡和链卡片随宽度减少列数。

只对宽表格启用局部横向滚动，避免整个页面溢出。页面保留清晰的主滚动区域，减少多层嵌套滚动。

### 10.5 样式作用域

建议使用跨链模块根容器与统一主题变量，集中管理颜色、间距、圆角与阴影。避免新增全局 `body`、`.ant-layout` 等覆盖规则影响其他区域。

可逐步抽取页面标题、统计摘要、业务卡片、状态标签、地址展示、步骤条、交易反馈、空状态与错误提示等公共组件。

## 11. 列表分页与反馈规范

### 11.1 数据分页

- 任务、交易、区块列表默认每页 10 条，支持切换 20/50 条。
- 筛选、排序和页码保存在地址参数中。
- 从详情返回时恢复列表上下文。
- 自动刷新不强制回到第一页，也不打断用户阅读。
- 根据现有接口能力选择服务端或前端分页；只取到部分数据时明确标识范围，不把当前批次数量冒充总数。

### 11.2 统一状态

| 状态 | 页面表现 | 用户后续动作 |
| --- | --- | --- |
| 加载中 | 骨架屏或局部加载，避免整页闪烁 | 等待，必要时取消当前操作 |
| 没有数据 | 原因说明与相关业务入口 | 发起任务、切换链或调整筛选 |
| 网络错误 | 保留已加载内容，显示错误与最后更新时间 | 重试或检查连接 |
| 钱包待确认 | 明确等待签名，禁止重复提交 | 在钱包确认或取消 |
| 交易已发送 | 展示交易标识与确认状态 | 查看交易进度 |
| 操作成功 | 展示业务结果 | 查看详情或继续下一步 |
| 操作失败 | 原因、可用证据与适用恢复路径 | 核对信息、查看交易或重新发起 |

## 12. 实施顺序

| 阶段 | 主要内容 | 阶段产出 |
| --- | --- | --- |
| 第一阶段 | 统一模块布局、主题变量、导航与基础组件 | 跨链区统一外观和页面骨架 |
| 第二阶段 | 发起跨链、我的任务、任务详情、工作台入口 | 普通用户业务闭环 |
| 第三阶段 | 跨链网络、链详情、交易与区块详情 | 可追踪的网络浏览路径 |
| 第四阶段 | 中继工作台、执行详情、区块搬运与质押 | 运营参与者业务流程 |
| 第五阶段 | 管理分页、异常状态、响应式和整体视觉检查 | 全部页面统一与交互收口 |

路由调整时兼容现有入口与详情链接，并保留链 ID、任务 Key 等必要上下文。第一阶段验收外观与导航，第二阶段重点验收普通用户完整流程。

## 13. 验收标准

1. 首次进入的用户能找到可用业务，理解所选链路和签名网络。
2. 用户能按说明完成填写，签名前核对业务内容、账户与费用。
3. 创建任务后可直接进入详情，并在离开后重新找到同一任务。
4. 用户能区分创建成功、执行中和执行成功，理解当前等待环节。
5. 中继参与者能区分任务执行与区块搬运，找到各自的准备步骤。
6. 所有状态和完成节点均有真实数据支撑，未知信息明确标识。
7. 各页面在浅色、深色和窄窗口下保持一致，无整页横向溢出。
8. 列表筛选与分页可恢复，操作反馈包含适用的下一步。
9. 新增样式不影响其他功能区，原有入口能够正确迁移或跳转。
