# Windows 浏览器 MetaMask 登录

在启动登录页点击 **Windows 浏览器 MetaMask 登录**。默认浏览器会打开本机认证页。在该浏览器的 MetaMask 插件中选择需要登录的账户，例如 `0x040AB1Cce91AA43981CB430CE9eD5A48866c7deE`，确认以 `login#punkos#` 开头的消息签名。认证成功后回到客户端继续使用。

不需要手机、二维码、私钥导入或链上交易。如果默认浏览器没有 MetaMask，可以把认证页的完整网址（包含 `#` 后的会话部分）复制到已安装插件的 Chrome 或 Edge。不要分享登录链接。

浏览器登录会先检查当前网络；如果不是 PunkOS，会请求切换，未添加时请求添加网络，确认实际 Chain ID 正确后才请求登录签名。签名期间切换网络会终止本次登录，可切回后重试。网络参数来自 `services/crosschain/data/dev/deployment.json`，与客户端共用部署配置。

当前部署的 RPC 是 HTTP 地址。客户端通过固定的本机地址 `http://127.0.0.1:18654/punkos` 转发到部署配置中的节点，利用 MetaMask 对回环地址的支持自动添加 PunkOS。启动转发前核实上游 Chain ID 为 `20260902`。仅监听回环接口，拒绝外部网站来源和节点签名/解锁方法；签名仍由 MetaMask 完成。退出客户端后此 RPC 停止，下次连接恢复同一地址。该转发不改变上游 HTTP 连接的传输方式。

登录和独立的钱包连接入口都会先添加/切换 PunkOS，确认实际 Chain ID 正确后才完成连接。用户随后切走网络会使业务钱包进入未就绪状态。若账户授权一直挂起，可点击“授权卡住？重新建立连接”创建新会话；有未完成的客户端请求时不能重建。

认证会话五分钟后过期，可在客户端或浏览器取消，再重新发起。拒绝钱包授权或签名后，可在浏览器重试。切换账户后需要重新签名。

登录成功后会在同一本地地址和端口跳转到浏览器交易钱包页，沿用登录时的 MetaMask 账户授权，自动同步连接状态；如果插件已锁定或授权已撤销，点击“连接 MetaMask”。保持此页打开，返回跨链页面即可看到连接地址和网络。已经登录的用户也可以直接从跨链页右上角菜单选择“连接浏览器 MetaMask”，无需退出重登。

跨链管理、创建任务、质押、接单和提交结果等通过共享 signer 发出的交易，将转发到浏览器钱包页。先核对账户、Chain ID、合约地址、金额和调用数据，再点击“核对无误，打开 MetaMask 确认”，最后在插件中确认。可以拒绝请求。切换账户、网络或锁定插件后，客户端会同步状态。

浏览器钱包被选中后，不会退回到环境变量私钥签名。需要使用其他钱包时，在右上角选择“连接其他钱包（WalletConnect）”。自动反向执行目标链交易的本地脚本仍是独立流程，浏览器钱包模式下会明确阻止使用它的私钥；可在目标链完成交易后手动填写交易信息提交结果。

关闭钱包页会断开交易连接，异常退出通过心跳检测断开。如果已经在插件中确认交易，但客户端出现超时，请先核查链上交易记录；系统不会自动重发。退出客户端会结束钱包会话，下次启动需重新连接交易钱包，登录身份不受影响。当前接入限定于跨链模块，其他模块仍使用原有钱包连接。

## 实现与验证

- 主进程 `src/main/browserWalletLogin.js` 启动随机端口的 `127.0.0.1` HTTP 服务，通过默认浏览器打开 `pages/browserWalletLogin/` 静态页，开发版和安装版共用这些资源，不依赖 Vite 服务。
- 使用现有 `server-config.js` 的 `config.NODE_SERVER_BASE_URL`，请求 `/api/users/login/nonce` 和 `/api/users/login/auth`。只有后端认证成功才回传用户信息给发起登录的客户端窗口。浏览器不会收到后端登录 token。
- 本地请求验证 Host、Origin、一次性会话凭据以及签名账户，nonce 在认证尝试时消耗。关闭客户端、取消、超时或页面导航会结束登录会话。
- 在根目录执行 `node --test scripts/test-browser-wallet-login.cjs` 检查签名回传、后端拒绝、重放、跨域访问、取消和超时。
- 执行 `node --test scripts/test-browser-wallet-bridge.cjs scripts/test-browser-wallet-login.cjs` 一起检查浏览器交易连接与登录。
- 真实 MetaMask 授权与签名需用户亲自确认；测试使用临时钱包和模拟后端，不产生真实链上交易。
